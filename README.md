# my-project
# 자봉이의 동네 구하기

작은 행동이 모이면 우리 동네가 달라져요! 청소년과 시민을 위한 약 2~3분의 모바일 웹 자원봉사 미니게임입니다. GitHub에 업로드된 자봉이 3D 원본을 시작·결과 화면 및 저장 PNG에 적용했습니다.


## RETRO RUN — 러너 버전

기본 화면은 **3D 카툰 자봉이 + 레트로 노을 배경의 3레인 러너**입니다. 기존 세 가지 미션은 `classic.html`에서 계속 플레이할 수 있습니다.

- 모바일: 좌우 스와이프 또는 아래 화살표 버튼으로 이동, 화면 탭·위 스와이프·JUMP 버튼으로 점프.
- PC: ←/→ 또는 A/D로 이동, Space/↑로 점프, Esc/P 또는 Ⅱ 버튼으로 일시정지.
- 2분 동안 달리면 완주합니다. 하트는 3개이며, 장애물은 레인을 바꾸거나 점프로 피합니다. 점프는 착지한 뒤 다시 할 수 있습니다.
- 온기 코인과 쓰레기 수거는 기본 10점. 연속 8개마다 배수가 올라가며 최대 5배입니다. 충돌하면 현재 콤보가 끊깁니다. 장애물을 뛰어넘으면 5점 보너스를 받습니다.
- 보호막은 10초 이내의 충돌 한 번을 막고, 자석은 9초 동안 옆 레인의 아이템도 모읍니다.
- 40초마다 노을빛 골목 → 나눔의 거리 → 온기 가득한 밤으로 바뀌며 속도가 점차 빨라집니다. 처음 7초 동안 생성되는 줄에는 장애물이 없습니다.
- 한 줄에 장애물은 한 레인만 차지하도록 생성하므로 피할 길이 있습니다. 아이템은 안전한 레인으로 안내합니다.
- 결과 화면에서 점수·거리·최고 콤보·온기, 기록 PNG 저장, 링크 공유, 재도전 및 1365 링크를 제공합니다. 온기는 수집 30개에 100%입니다.
- 러너 최고 점수는 `jabongi-runner-best`로 별도 저장하며 기존 미션 최고 점수는 유지합니다. 다른 탭으로 이동하면 자동 일시정지합니다.

### 러너 파일

`src/runner.js`: 러너 UI·입력·오디오·결과·공유. `src/runner-engine.js`: 독립된 물리·레인·충돌·점수·아이템 규칙. `src/runner-renderer.js`: Canvas 2D를 이용한 원근감 있는 2.5D 도로, 입체 건물·장애물, 레트로 일몰과 배경 이동. 실제 3D 모델/WebGL 엔진은 사용하지 않으며, 자봉이는 제공된 3D 렌더링 이미지입니다. `src/runner.css`와 `src/style-base-runner.css`: 반응형 게임 UI.

`assets/characters/jabongi-runner.png`는 제공된 점프 포즈 `jabongi-10.png`에서 배경 제거만 요청해 Image Gen으로 만든 파생 파일입니다. 원본 PNG 12개는 편집·삭제하지 않았습니다. 원본 디자인과 비율을 유지하도록 요청했으며, 게시 전 권리자 관점의 최종 확인이 가능합니다.

`tests/runner-engine.test.js`는 이동 경계·점프·충돌·무적·보호막·자석·콤보·안전 경로·2분 완주를 검증합니다. `tests/runner.spec.js`는 모바일·PC에서 실제 조작·일시정지·게임오버·재도전·PNG·320px 화면·저장소 차단을 검증합니다. 기존 미션 테스트도 함께 실행합니다.

아래의 세 미션·300점 설명은 **차근차근 미션 모드(`classic.html`)**에 해당합니다.

## 실행

Node.js 22 이상에서:

```sh
npm ci
npm run dev
```

표시되는 로컬 주소를 브라우저에서 엽니다. 같은 네트워크의 모바일에서는 터미널의 Network 주소로 접속합니다. 모듈을 사용하므로 `index.html`을 파일로 직접 열지 말고 개발 서버를 이용하세요.

```sh
npm test       # 점수 규칙 테스트
npm run build # 배포용 dist 생성
npm run preview # 배포 빌드 확인
```

## 프로젝트 구조

```text
index.html                 한국어 진입 페이지
src/main.js                화면 전환, 플레이, 일시정지, 소리, 저장, 공유
src/config.js              미션 문구, 물건 분류, 이웃 문항, 캐릭터 경로
src/scoring.js             독립 점수 계산
src/art.js                 원본 SVG 마을과 임시 도형
src/style.css              모바일 우선 반응형 UI와 애니메이션
assets/characters/         공식 자봉이 원본 이미지 위치
assets/favicon.svg         아이콘
 tests/                    점수 단위 테스트 및 브라우저 플레이 검증
.github/workflows/pages.yml GitHub Pages 자동 배포
```

터치 선택 중심인 이번 버전은 Phaser 대신 기본 DOM/SVG로 구현했습니다. 무거운 게임 엔진 다운로드 없이 실행되며 버튼의 키보드 조작과 스크린리더 설명을 제공합니다. 런타임 외부 API, CDN, 폰트, 서버, DB가 필요하지 않습니다. 개발·빌드 도구는 Vite입니다.

## 플레이 및 점수

시작 → 마을 지도 → 원하는 미션 선택 → 미션 완료 → 지도 → 세 미션 완료 → 최종 결과. 미션 순서는 자유이며 같은 도전에서 완료한 미션은 다시 점수를 주지 않습니다. 결과 화면의 다시 도전으로 모두 초기화합니다.

- LEVEL 1: 쓰레기 6개 수거, 목표 35초. 마지막 수거 후 밝은 마을과 완료 효과를 표시합니다.
- LEVEL 2: 물건 선택 후 공부/생활 상자 선택. 오답은 힌트를 제공하고 재시도하며 목표 40초입니다.
- LEVEL 1·2: 수행 6×10점 + 완료 20점 + 콤보 최대 10점 + 속도 최대 10점. 4초 이내 연속 성공마다 콤보 2점, 한 미션 내 최고 연속 기록을 반영합니다. 오답은 현재 연속 기록을 끊습니다. 속도 = `max(0, round(10 × (1 - 경과초 / 목표초)))`이며 시간 초과는 속도 0점, 게임오버가 아닙니다.
- LEVEL 3: 먼저 의사 묻기, 거절 존중, 원하는 도움 제안하기의 세 문항. 정답에 이를 때까지 힌트와 재도전, 각 정답 20점 + 완료 40점. 시간제한 없습니다.
- 총점 300점, 온기는 완료한 미션에 따라 0 → 33 → 67 → 100%입니다.
- 잠시 쉬기 또는 다른 탭으로 이동 시 시간이 멈춥니다. 진행 중 페이지를 새로고침하면 이번 도전은 초기화됩니다.
- LocalStorage에는 최고 점수(`jabongi-best`)와 소리 설정(`jabongi-sound`)만 저장합니다. 저장소가 차단되어도 게임을 할 수 있습니다. 소리는 기본 OFF이며 사용자 조작 이후 Web Audio로 재생합니다.

## 공식 이미지와 내용 수정

업로드된 원본 12개는 `assets/characters/jabongi-01.png`~`jabongi-12.png`로 편집 없이 보관합니다. `sources.json`에서 GitHub 원본 파일명과의 대응을 확인할 수 있습니다. 현재 선택은 흰 배경의 점프 포즈 `jabongi-10.png`입니다. 체크무늬나 흰 배경도 원본의 일부로 보존하며, 캐릭터 디자인·비율을 변경하거나 배경을 제거하지 않았습니다.

다른 공식 파일을 `assets/characters/`에 넣고 `src/config.js`의 `CHARACTER_PATH`를 파일명으로 지정합니다. 원본 비율을 유지해 시작·결과 화면과 결과 PNG에 표시하며 원본을 변형하지 않습니다. 경로가 잘못되면 임시 도형을 유지합니다. Windows PC의 폴더 경로는 웹/클라우드에서 직접 접근할 수 없으므로 파일 자체를 저장소에 추가해야 합니다.

미션 문구/분류/이웃 선택지는 `src/config.js`, 점수는 `src/scoring.js`, 색상/배치는 `src/style.css`에서 수정합니다. 물건 수와 문항 수를 바꾸려면 점수와 진행 표시도 함께 수정하세요. 이모지 아이템은 운영체제에 따라 외형이 달라집니다.

## 결과 저장 및 공유

최종 점수와 마을, 캐릭터를 Canvas로 그려 PNG 다운로드를 제공합니다. 모바일 브라우저에서 자동 저장이 안 되면 표시되는 다운로드 링크를 이용합니다. 네이티브 공유가 있으면 공유 창을 열고, 없으면 게임 주소를 복사합니다. 클립보드도 사용할 수 없으면 선택 가능한 주소 입력창을 표시합니다. `1365` 버튼은 새 탭에서 공식 자원봉사 포털을 엽니다.

## GitHub Pages 배포

1. GitHub 저장소 Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 선택합니다.
2. 코드를 main 브랜치에 반영하거나 Actions의 `Deploy game to GitHub Pages`를 수동 실행합니다.
3. 작업이 완료되면 Pages에 표시되는 주소에서 플레이합니다. 이 저장소라면 일반적인 주소는 `https://handssumboy-oss.github.io/my-project/`입니다(배포 설정에 따라 다름).

`vite.config.js`의 `base: './'`로 빌드된 CSS/JS/이미지를 상대 경로로 로드하므로 저장소 하위 경로에서도 동작합니다. 소스가 아닌 **dist**를 배포합니다. GitHub Pages 도메인과 HTTPS 환경에서 공유 기능을 확인하세요. 이 작업에는 배포 설정 파일이 포함되며 원격 게시 실행 여부는 별도 확인이 필요합니다.

## 브라우저 검증

```sh
npx playwright install chromium
npm run test:e2e
```

테스트 설정은 `/usr/bin/chromium`이 있으면 사용하고, 없으면 Playwright 설치 브라우저를 사용합니다. 별도 브라우저는 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 환경변수로 지정할 수 있습니다. 배포 워크플로에서도 브라우저를 설치하고 전체 플레이 테스트를 실행합니다.

390px 모바일/1440px 데스크톱에서 전체 미션 플레이, 오답 재도전, 자유 선택 순서, 중복 완료 방지, 일시정지, 최고 점수 유지, PNG 파일, 목표시간 초과, 320px 가로 넘침, LocalStorage 차단을 확인합니다. 실제 iOS/Android 기기의 저장·공유 UI는 기기별 추가 확인을 권장합니다.
